# DC27 conference production on Fire Producer + Tronix

**Status: experimental prototype. Not a certified AV switcher or deployed DC27 system.**

DC27 is April 28–30, 2027 in Washington, DC. This prototype is a three-day,
operator-controlled conference guide inspired by a television programming grid.
**Every seeded session is a DEMO placeholder, not DIG's actual agenda.**

## Surfaces

- Public grid: `/?cartridge=conference&event=dc27&mode=viewer`
- Solo-producer board: `/?cartridge=conference&event=dc27&mode=operator`
- API: `/api/events/conference/dc27/{state,events,command,ws}`

The producer can select a day and session, move sessions through
`scheduled → ready → live → ended` (plus `delayed`), add sessions,
log stage cues, and report readiness per room. The common EventDO authority
records every successful command with a sequence, actor and idempotency key,
then fans updated state out to both projections over WebSockets.
Simultaneous `live` sessions are rejected **within the same room**.

The UI intentionally does **not** claim to switch HDMI sources, patch microphones,
start physical recording, provide live ASL, or generate captions. All equipment
readiness dropdowns are **manually reported**; a WebSocket connection indicator
is only the event authority connection, not video uplink health.

## Running locally

```sh
npm ci
npm run check
# separate terminal / Wrangler local secret provision
printf 'PRODUCER_TOKEN=%s\n' "$PRODUCER_TOKEN" > .dev.vars && chmod 600 .dev.vars
npm run worker:dev
```

The token must be at least 24 characters. In deployed Cloudflare Workers,
configure it with `wrangler secret put PRODUCER_TOKEN` in the correct
environment. Never commit this token, embed it in browser bundles, or put it in
a URL. Operator browsers hold the entered token in memory only, cleared on
refresh; public viewers do not need a token. The Worker **fails closed**
(503) for conference writes if no usable token is configured, and returns 401
on a mismatched Bearer token. Other existing cartridges have their preexisting
write policies and must not be treated as secured by this addition.

Inspect GET `.../state` for current state and `.../events` for full journal.
Send commands with `Content-Type: application/json`,
`Authorization: Bearer <PRODUCER_TOKEN>`, and a unique `idempotencyKey`.

Example (update a sample session):

```json
{"type":"SET_SESSION_STATUS","sessionId":"demo-open","status":"ready","idempotencyKey":"dc27-ready-001"}
```

## Tronix local bridge

Tronix is an **experimental native Apache Celix/MessagePack agent runtime**
with a restricted local AF_UNIX socket. Fire Producer remains the single
writable event authority for this prototype. A Node bridge on the venue
operator machine reads Tronix's **ping and scheduler snapshot only**, then
reports `tronix` scheduler reachability to Fire Producer as a `SET_SIGNAL`
in the show-wide signal namespace. It does not `submit`, run adapters, expose
a Tronix socket publicly or send cues to hardware. This is a functional,
read-only integration, not actual switcher control.

```sh
export TRONIX_CLIENT_PATH=/absolute/path/to/tronix/src/client.mjs
export TRONIX_SOCKET=/absolute/private/path/to/tronix.sock
export FIRE_PRODUCER_URL=https://your-fire-producer.example
export PRODUCER_TOKEN=...  # same protected production token; do not log
node tools/tronix-conference-bridge.mjs --once
# Or omit --once for a periodic local health probe (default 15 seconds).
```

Requires the Tronix checkout's pinned Node MessagePack dependency and a
running private daemon, following its own setup instructions. Only writes on
status changes; `ok` indicates scheduler reachability, **not** actual camera,
caption, microphone or recording equipment readiness. Use a dedicated
least-privilege token once per-actor roles are implemented.

## Boundaries and show-day checklist

1. Replace demo placeholders with the approved DIG program before sharing a
   public board. Operator edits are event-sourced; no bulk import yet.
2. Verify captions and ASL interpreter feed **at each venue endpoint** with a
   human operator. The grid must never be interpreted as accessibility QA.
3. Assign room staff for simultaneous sessions. One producer cannot physically
   monitor every room, replace a failed cable, or resolve an emergency remotely.
4. Perform off-air hardware tests for source changes, microphones, backup
   recordings, on-screen graphics, captions and interpreter views.
5. Retain independent local recordings, printed/run-sheet backups, UPS power
   and a manual fallback in every room.
6. Do not bridge Cloudflare and a separate native authority as simultaneous
   writers. Any Celix authority migration requires replay parity, exclusive
   authority and a separate security review.

- Real caption/ASL transport, preview confidence and human-visible fault alarms.
